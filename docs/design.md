# 设计文档

## 1. 背景与目标

本项目面向公务员和事业单位面试备考场景，解决备考者“缺少随机真题训练、缺少即时反馈、语音练习不方便、答题建议空泛”的问题。

系统目标：

1. 支持省考、国考、事业编面试题随机训练。
2. 支持按年份和考试类型定向训练。
3. 支持语音和文字两种作答方式。
4. 作答后获得可量化评分和结构化建议。
5. 评分结果可沉淀到数据库，便于后续扩展个人训练档案。

## 2. 用户流程

1. 用户进入首页。
2. 选择考试类型和年份，或保持“全部”。
3. 点击“随机出题”。
4. 系统从 MySQL 查询可用题目，并通过 Redis 短时缓存年份等热点元数据。
5. 用户通过文字输入或浏览器语音识别输入答案。
6. 用户点击“提交评分”。
7. Java 后端读取题目、构造评分 Prompt、调用 DeepSeek API。
8. 系统解析 JSON 评分结果，存入 MySQL 并返回前端展示。

## 3. 评分维度

总分 100 分：

| 维度 | 分值 | 说明 |
| --- | ---: | --- |
| 审题准确度 | 20 | 是否抓住核心矛盾、身份定位、任务要求 |
| 政策理解与价值立场 | 20 | 是否体现服务群众、依法行政、实事求是等公共价值 |
| 分析深度与逻辑结构 | 20 | 原因、影响、主体分析是否清晰充分 |
| 对策可行性 | 20 | 措施是否具体、可执行、符合基层实际 |
| 表达流畅度与面试风格 | 20 | 语言是否规范、自然、有现场感 |

## 4. DeepSeek 输出结构

后端要求模型只返回 JSON：

```json
{
  "score": 86,
  "level": "优秀",
  "strengths": ["优点"],
  "weaknesses": ["不足"],
  "contentAdvice": "内容建议",
  "structureAdvice": "结构建议",
  "expressionAdvice": "表达建议",
  "answerFramework": ["解题步骤"],
  "goldenSentences": ["金句"],
  "sampleAnswerOutline": ["参考提纲"]
}
```

## 5. 数据设计

### questions

存储题库。核心字段：年份、考试类型、地区、来源、标签、题目正文、启用状态。

### evaluations

存储评分记录。核心字段：题目 ID、考生答案、分数、等级、完整 JSON 评分结果。

## 6. 语音输入设计

前端使用浏览器 `SpeechRecognition` / `webkitSpeechRecognition`，优点是无需额外后端语音服务，部署简单。若浏览器不支持，系统提示用户改用文字输入。

## 7. 安全设计

- DeepSeek API Key 只在服务端通过环境变量读取。
- 前端不暴露密钥。
- `.env.example` 只提供占位符。
- 后端对答案长度进行校验，避免空内容或超长内容直接调用模型。
